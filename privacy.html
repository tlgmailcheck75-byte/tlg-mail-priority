Privacy Policy

TLG Mail Priority (Android app and website) · Last updated 3 November 2026

TLG Mail Priority's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

1. Who this applies to

TLG Mail Priority is a private, non-commercial tool used inside one small accounting team. It is not sold, not advertised and not offered to the general public. It comes in two forms that share a classification engine but store things differently, so both are described below:

  • the Android app, installed directly on a phone;
  • the website, which runs entirely in the user's own browser.

2. What is accessed

Only after the user signs in on the provider's own screen and grants permission:

WherePermissionWhat it allows
Android app — Google gmail.readonly Read Gmail messages. Nothing else.
Android app — Microsoft Mail.Read, offline_access, User.Read Read Outlook messages, stay signed in, and read the signed-in address.
Website — Google gmail.readonly Read Gmail messages. Nothing else.
Website — Google drive.appdata Read and write only the app's own hidden folder in the user's Google Drive, used to keep the phone and the website in step. It gives no access to any other Drive file, and the app cannot see the rest of the user's Drive.

From each message, the sender, recipients, subject, date, message text, labels or folder, thread information, and the file names, types and sizes of attachments are read. Attachment files themselves are never downloaded. Every mail permission above is read-only: nothing can be sent, replied to, forwarded, deleted, labelled or changed in the mailbox.

Beyond its own hidden folder, no access to Drive, Contacts or Calendar is requested.

3. How the data is used

  • To sort each thread into an accounting category, set a High, Medium or Low priority, write a short summary and suggest an action.
  • To show what is overdue, due today or still waiting, until the user marks it done.

All of this is worked out on the user's own device — the phone, or the browser on their computer. Mail is not used for advertising, is not sold, and is not used to train any AI or machine-learning model.

4. Where the data is kept

This is the part worth being exact about, so it is set out in full.

DataAndroid appWebsite
Message content — subjects, bodies, senders, attachment names — and what is worked out from it The phone's memory only, while the app is open. It is not written to a file and not uploaded. Closing the app discards it. The browser's own storage (IndexedDB) on that computer. It is not uploaded anywhere.
Sign-in tokens The app's private storage on the phone. They go nowhere but back to Google or Microsoft. Held by the browser for the session, through Google's own sign-in library.
The user's own work state — what is marked Done or Waiting, their notes and reminders, and any category or priority they set by hand The app's private storage on the phone, stored against the provider's thread identifier alone — no subject, sender or message text. A single JSON file in the hidden app folder of the user's own Google Drive, so the phone and the website agree. It holds thread identifiers and the user's own entries. No message text is written to it. Nobody else, including the developer, can read that folder.
Account (email address, name, whether the user is an admin) and the categories, keywords, rules and VIP addresses the team has set up A database hosted by Supabase, so settings follow a person between devices and an admin can set them for the team. No message content is ever stored there. In the same Google Drive hidden app folder as the work state above.

In short: the Android app does use a server, and it holds the user's account and the team's category settings — but never a line of anyone's mail. Mail is fetched by the device, straight from Google or Microsoft, and stays on that device.

5. Sharing

Google and Microsoft user data is not shared with anyone. The only network connections made are to Google's and Microsoft's own sign-in, mail and Drive services, and — from the Android app — to the Supabase database described above. There are no analytics, trackers or advertising services in either the app or the website.

6. Deleting your data

  • In the Android app, open You → Mailboxes → Disconnect. The sign-in tokens for that mailbox are deleted from the phone. Uninstalling removes everything it holds.
  • On the website, clearing the site's data in the browser removes the stored mail.
  • The synced work-state file can be deleted at any time in Google Drive → Settings → Manage apps → TLG Mail Priority → Options → Delete hidden app data.
  • Revoke access at any time at myaccount.google.com/permissions (Google) or myapplications.microsoft.com (Microsoft).
  • To have the account and settings removed from the database, write to the address below and they will be deleted.

7. Security

Sign-in uses OAuth 2.0; the Android app uses PKCE in the system browser. The user's password is never entered into, seen by, or stored by the app or the website. The database enforces row level security, so each person can read only their own account and the settings shared with their team.

8. Changes

If what is done with data changes, this page is updated and the date at the top changes with it.
